# 2026-08-29 · Device discovery scope — what a device may be learned from

> Not an experiment log. A boundary, in the same sense as the lens-scope entries
> of 2026-08-19: it exists so that later readers — human or agent — stop
> re-proposing routes that are already ruled in or out, and stop citing a
> hypothesis as if it were a measurement.
>
> Occasioned by a stale claim. Four places in this repository still described
> [`reference/npcd-command-set.md`](../../reference/npcd-command-set.md) as
> extracted from the vendor DLL, months after it was regenerated by reading the
> live controller. Fixed here; see "What this corrects in the record".

## Context

Three subsystems do not describe themselves through any registry this project
already trusts. The piezo is outside Micro-Manager and speaks a vendor DLL. The
tweezers are outside it too and speak 28 TCP commands plus an undocumented
embedded-Python node tree. The LUN-F combiner is in neither control stack and
its DAC word format is not published at all. For each of them, "what can this
device do" has had to be **found out** rather than looked up.

## Scope — two off-instrument routes, and one rung above both

| Rung | Route | Produces | Standing |
|---|---|---|---|
| **1** | **Read off the live device** — `find_commands()`, `--describe`, a probe that answers, a measured value | a fact about **this unit** | **measured.** The only rung that settles anything |
| **2** | **The vendor manual** and published documentation | a claim about the **product family** | assumed — and the family is usually wider than this unit |
| **3** | **Reverse engineering the vendor's own files** — `strings` over a DLL, introspection of the GUI's embedded Python, vendor config files, and a USB capture as a last resort | a **hypothesis** | assumed, and explicitly provisional |

### The rule

**A rung-2 or rung-3 fact may be used to write code. It may not be used to claim
a capability.** It is labelled where it is used, and it stays labelled until a
rung-1 read replaces it — the same discipline
[`kb/literature/`](../literature/) already applies to published values, and for
the same reason: what buys the label is that a gate can compute instead of
refusing, not that a verdict can advance.

### Discovery is read-only

Nothing may be *written* to a device in order to find out what it does.
`find_commands()`, `--describe`, `ReadNode`, `dir()`/`inspect` and `strings` all
qualify. Probing by sending is allowed only where the refusal **is** the answer
and the command cannot act if it exists: the tweezers' 52 probed command names
were each sent with three junk arguments, so a command that existed would fail
to parse rather than execute, and `-11` arrives before argument parsing. That is
a clean existence oracle and not a write.

### Vendor support is a parallel track, never a blocker

Asking the vendor is allowed and is not a third rung — a reply is rung 2 with a
better address. It runs *alongside* the measurement, never in front of it:
[`kb/systems/aresis-support-email-draft.md`](../systems/aresis-support-email-draft.md)
and [`PyTool-RUN-FIRST.md`](../systems/PyTool-RUN-FIRST.md) are deliberately
independent, either one useful alone and together a cross-check. **No task waits
on a reply.** When one arrives, only the technical facts it settles are recorded,
with the reply and its date named as their source; the correspondence itself
stays out of this repository ([NOTICE](../../NOTICE.md)).

## The worked example, and what the rung-3 route cost

`reference/npcd-command-set.md` held **178** command names pulled out of the
64-bit DLL with `strings`. The file said plainly that they were a family-wide
superset and a hypothesis to confirm. Reading the live controller on 2026-08-27
returned **414** at User level, and moved the count in both directions:

- **The extraction could not see hyphens.** Real names carry them, so
  `function.waveform-generator.*`, `function.waveform-builder.*`,
  `resonance-detect.*` and `diagnostics-logging.*` were invisible to the regexp
  — and *the same blind spot sat in `piezo_stage._COMMAND_LINE` and in the test
  that checks every command the module sends against the reference*. **That test
  was passing by not seeing the names it was meant to check.**
- **Names from other controllers in the family do not exist here.**
  `fpga.*`, `peek.*`, `system.*`, `stage.command.digital.scaling.*` and
  `stage.command.analogue.scaling.gain/offset` all answer "Invalid command name".
- **One of those non-existent names had been cited as evidence.**
  `2026-08-26-piezo-waveform-generator.md` used the analogue/digital scaling pair
  as "direct evidence" of two independent command paths. The paths are real, but
  that evidence for them was an artifact of reading another model's names out of
  a shared DLL.

The failure mode to carry forward: **a rung-3 list is wrong in both directions at
once**, and the direction that hurts is not the missing names — it is the names
that are present, plausible, and belong to a different unit.
→ [`2026-08-27-piezo-first-light-measured-limits.md`](2026-08-27-piezo-first-light-measured-limits.md) §8

## What this corrects in the record

Four places described the command set by the route it no longer comes from:

| Where | Said | Now |
|---|---|---|
| [`NOTICE.md`](../../NOTICE.md) | "extracted from the 64-bit binary, with the extraction command and the binary's md5 in its header" | read off the live controller; the header carries the port, firmware and the command that regenerates it |
| [`docs/01`](../../docs/01-architecture.md) folder tree | "extracted from the vendor DLL" | read off the controller |
| [`docs/07`](../../docs/07-roadmap.md) Phase 5 | "Established offline by extracting the command names from the vendor DLL — 178 commands with a superset caveat" | established on the controller — 414 names, and the waveform families were among those the DLL route had missed |
| [`config/piezo/verify_piezo_commands.py`](../../config/piezo/verify_piezo_commands.py) | "was extracted from a DLL that serves the whole family — so it is a superset and a hypothesis. `--describe function` settles it" | the hypothesis was settled; the script's remaining job is the parameter layout, not the existence question |

None of the four was wrong when written. They went stale on 2026-08-27 and
nothing pointed a reader at the newer file, which is the ordinary way a
provenance claim outlives its provenance.
